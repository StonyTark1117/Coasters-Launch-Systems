# Coasters: Launch Systems 1.0.1

**Use Launch Systems 1.0.1 with Fourth Dimension 1.6.0.** This companion release
adds the accepted FD 1.6 moving-track handoff while retaining standalone
operation and the previously qualified fixed-track equipment certificates.
Launch Systems 1.0.0 does not include the FD 1.6 adapter.

## Changes

- Support native original Arrow and Wing moving-bed handoffs with fixed local
  Tire/LSM/LIM equipment and fin brakes. FD retains the train during movement;
  LS applies no propulsion or braking permission during native retention.
- Require a locked destination, FD Release, explicit receiving-controller arm,
  and a separate fresh launch request. Restart, provider loss and missing
  controller hardware cannot replay requests or substitute a different owner.
- Allow eligible fixed Arrow dock cabinets below the moving sweep, within four
  blocks total distance and 1.025 blocks horizontally. The 25mm horizontal
  allowance matches FD's locked-socket tolerance and requires live dock
  authentication. Ordinary mounts retain their three-block limit.

Moving support remains limited to the documented original Arrow/Wing contract;
cable and swing operation, managed FD circuits, other families and transfers
during bed motion are outside that certificate. A configured fixed Tire exit
can operate after docking. See the [moving handoff guide](https://github.com/StonyTark1117/Coasters-Launch-Systems/blob/v1.0.1/docs/FD16-MOVING-HANDOFF.md)
for setup, normal controls and recovery.

## Installation

Replace the old LS JAR with `coasters-launch-systems-1.0.1.jar` on the server and
all clients. Use Minecraft 1.21.1, Java 21, NeoForge 21.1.256, Create 6.0.10,
Create: Coasters Simulated 0.1.5 and Sable 2.0.6, with the same bundled library
versions as the [1.0.0 installation stack](https://github.com/StonyTark1117/Coasters-Launch-Systems/blob/v1.0.0/docs/releases/1.0.0.md#install-the-qualified-stack).
For current combined operation, install **Fourth Dimension 1.6.0**. FD remains
optional for ordinary carts. Exact FD 1.1.0/schema-8 API1 snapshot support is
retained; FD 1.6.0/schema-9 additionally requires its moving API1 contract.
