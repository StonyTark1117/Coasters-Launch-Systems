# Coasters: Launch Systems 1.0.0

Launch Systems 1.0 is a standalone addon for Create: Coasters Simulated on
Minecraft 1.21.1. It brings six launch mechanisms, physical braking hardware,
and local ride control to ordinary carts, with separately qualified support
for an exact optional Fourth Dimension snapshot.

## Ride equipment

- **Drive tires, LSM and LIM:** shaft-powered tires and distinct linear reaction
  plates, with finite energy, acceleration and heat limits. Linear controllers
  also support a bounded forward/backward/forward launch program.
- **Flywheel, hydraulic and pneumatic launches:** three finite stores driving
  a physical carriage and catch. A new cycle requires the carriage's actual
  HOME return as well as sufficient charge.
- **Five braking choices:** friction-fin clamps for the rated final stop and
  hold; skid and passive magnetic trim; powered LSM/LIM deceleration; and
  drive-tire retardation. Passive magnets and skid brakes do not replace a
  holding fin bank. Braking does not generate free energy.
- **Local ride control:** ordered spans, loaded stopping-distance checks,
  retained whole-train reservations, boarding signals, supported station capture
  and tire transfers. A fresh ready-state lever edge or operator request starts
  departure; held-high input never repeats a launch.

Recipes and four in-game Ponder guides cover installation. Start with the
[operator guide](https://github.com/StonyTark1117/Coasters-Launch-Systems/blob/v1.0.0/docs/OPERATOR-GUIDE.md), then use the mechanism's placement and
commissioning instructions. Launch sections and cable guides require the
specified fixed, level, unbanked geometry and correctly mounted interfaces.

## Install the qualified stack

Use the same selected mod set on the server and clients. Fourth Dimension is
optional; it is not needed for ordinary-cart operation. Launch Systems does not
bundle the dependencies or other coaster addons.

Install [NeoForge 21.1.256](https://maven.neoforged.net/releases/net/neoforged/neoforge/21.1.256/neoforge-21.1.256-installer.jar)
for Minecraft 1.21.1, then place `coasters-launch-systems-1.0.0.jar` and these
upstream releases in the instance's `mods` directory:

- [Create 6.0.10](https://www.curseforge.com/minecraft/mc-mods/create/files/7963363)
- [Create: Coasters Simulated 0.1.5](https://www.curseforge.com/minecraft/mc-mods/create-coasters-simulated/files/8655742)
- [Sable NeoForge 2.0.6](https://www.curseforge.com/minecraft/mc-mods/sable/files/9043865)

Use the full upstream distributions. Their bundled libraries supply the selected
Flywheel, Ponder, Registrate, Companion and Veil components listed below; avoid

## Optional Fourth Dimension support

Combined operation is qualified against the accepted FD 1.3 implementation
baseline with the additive authority, family-power, route and operator API 1
contracts. That snapshot still reports **1.1.0 / save schema 8**. Its selected
file is `fourthdimension-route-operator-tagged-api1.jar`, SHA-256:

```text
d676d730a02c6f9abe217985db03a3bca424892f06236a0cf64e066b82e87738
```

This is a local, unpublished qualification snapshot, not a publicly available
FD release or an included download. Standalone installation needs no FD. A
matching version label or schema alone is insufficient. Published FD 1.5.0,
older schema-8 JARs without these contracts, and other sibling builds are not
interchangeable with this qualified input. Consult the exact
[FD handoff](https://github.com/StonyTark1117/Coasters-Launch-Systems/blob/v1.0.0/docs/FOURTH-DIMENSION-HANDOFF.md) before installing it.

The [certificate table](https://github.com/StonyTark1117/Coasters-Launch-Systems/blob/v1.0.0/docs/FD-VEHICLE-CERTIFICATES.md) specifies the eligible
mechanical variants, mounted interfaces and operating conditions. FD retains
control of seats, restraints, rotation, posture and capture. Managed routing is
limited to the accepted original-Arrow circuit with eight segments, six blocks
and at most three trains; FD owns its current/next reservations.

Suspended and New-generation Flying have no cable-launch certificate because
of guide clearance. Powered Inverted Yaw, Roller Ball and PAX are excluded from
LS equipment operation. Appearance choices never grant a hardware certificate.

## Existing worlds and recovery

Back up the world before upgrading or removing a vehicle-owning mod. The saved
provider ledger introduced in 0.9 prevents an observed optional-provider vehicle
from silently becoming an ordinary launch-ready cart when that provider is absent.
For a pre-0.9 world, first load and inspect the affected vehicles with their
provider installed under 0.9 or later, then save before removing it. Unvisited
older vehicles have no ownership record that LS can infer retroactively.

After interruption, restart, power restoration or provider restoration, inspect
the retained state and explicitly recover/rearm as documented. A separate fresh
request is still required; loading or rejoining does not replay departure.
Removing a reservation does not repair a fault or recreate missing mod blocks.

## Boundaries and qualification

This release does not advertise the optional LS801–LS807 adapters: Engineered,
Magnetized, Additions, Track Styles, FE/Jade/JEI/EMI/Immersion presentation,
positive PAX final-brake handoff or CTNB. Existing
conflict refusals are not positive integration support. General FD routing,
positive PAX delegation, later FD specialty vehicles, moving-track launch
interfaces, linear station/transfer cycles and park scheduling remain excluded.

The accepted [0.9 qualification](https://github.com/StonyTark1117/Coasters-Launch-Systems/blob/v1.0.0/docs/evidence/0.9/integration-20261127/README.md)
combines ordinary and real occupied FD demonstrations of all six launches,
finite family/mechanism certificates, saved-provider and interruption recovery,
resource accounting, measured callback costs, and packaged asset/instruction
checks. Version promotion reuses that accepted behavior; it does not expand the
supported dependency or optional-integration matrix.
