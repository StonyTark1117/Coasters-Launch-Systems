# Ride-local operator controls

For the bounded original Arrow circuit, Fourth Dimension owns admission and current/next route blocks. Launch Systems owns its installed equipment, stopping-region reservation, charge and transient launch request. The native operator panel and the controller/cabinet right-click status read the same live LS snapshot. This adds no separate park-control screen.

The panel keeps native whole-consist occupancy, restraints, capture and vehicle controls. Its Controller line identifies the exact LS controller UUID and local phase; Power reports stored work and capacity, or continuous shaft supply when the installation has no finite store. Dispatch shows the current blocking reason. The request line distinguishes a pending request from the need for a new input. Native route train identity is distinct from equipment-controller identity: route blocks belong to the admitted train, while the installed controller owns the equipment lease.

Use **Dispatch** to submit one fresh request to the normal LS controller loop. It does not directly release FD authority. The server rechecks vehicle revision, controller identity, permission, proximity, local request revision, route permission and live equipment guards. A request denied while blocked is discarded; restoring power, clearing another train, reconnecting or loading a save cannot replay it. A physical controller lever remains a fresh low-to-high input; holding it high does not retrigger. An explicit new panel click is a separate fresh input even while the lever remains high.

Use **Hold equipment** to disarm the local controller and retain its reservation. An active cable catch still requires physical return or its existing inspected recovery; the button cannot bypass that guard. **Resume authority** requests explicit local rearm/recovery and leaves the train held. Review the refreshed state, resolve the reported native or route guard, then make a separate fresh Dispatch request. A successful native station capture deliberately marks the route braked and suspends travel authority. To continue, inspect and explicitly disarm/rearm the controller (or use Hold equipment then Resume authority); the route and native authority resume while the train remains captured. A separate fresh request starts transfer. Normal native Capture and vehicle/restraint controls remain available. A native vehicle-editor Dispatch/Resume lacking the LS request revision directs the operator back to the existing operator panel instead of bypassing LS.

Controller request revisions and queued requests are transient. Loading a controller preserves its identity and reservation but enters inspection, clears input history and requests, and creates a new request revision. Resume is not dispatch. A missing/replaced controller or changed whole consist cannot borrow the old controller's permission.

## Contract and focused qualification

The additive FD API1 provider callbacks are `operatorStatus(ServerLevel, Vehicle)` and `operatorAction(ServerLevel, Vehicle, int, long)`. `RideAuthority.externalOperatorStatus` and `externalOperatorAction` resolve the registered provider and exact current owner. The LS `OperatorStatus` adapter is shared by the native panel callback and local status messages. Its snapshot includes owner, phase, blocked reason, charge, pending/fresh request state and transient request revision. `FourthDimensionRouteStatus` reports the existing native route owner and current/next block grant.

The native external-panel fixture adapts `ToolsAuthorityGameTests` and `ExternalRideAuthorityGameTests` from the selected FD baseline. It exercises registered-adapter sampling, identical owner/charge/denial, stale/repeated request rejection, controller loss, range guards and queue-only service. The LS fixture uses an actual native Arrow and installed LS controller to compare both snapshots and check request consumption/reload. The delegated-route fixture uses a real eight-segment Arrow circuit and native bodies, with opt-in, conflicting ownership, opposing direction and unloaded-body checks. The occupied multi-train and restart/rejoin proof is recorded separately in the 0.6 evidence; fixture coverage alone is not that player proof.

The [accepted LS operator receipt](evidence/0.6/ls602-operator-20261126/README.md) records the actual Arrow/controller status and request check, fixture corrections, immutable FD artifact and saved shutdown. The [route integration record](evidence/ls06-route-20261126/README.md) owns physical conflict, occupied and lifecycle outcomes.

The [occupied operator-panel record](evidence/0.6/ls602-operator-20261126/occupied-observer/README.md) preserves rendered owner, power, blocked reason and fresh-request state with normal button input, alongside the route owner’s physical and saved-world evidence.
